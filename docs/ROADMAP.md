# План разработки NetTurn (Внутренняя документация)

> **Статус**: План реализации  
> **Целевой стек**: Go 1.23+ (Core & Server), Wails v2 / React (Linux Desktop), Kotlin / Compose (Android)  

План разделен на 7 последовательных этапов с критериями готовности (DoD — Definition of Done).

---

## 📌 Этап 1: Фундамент ядра и криптография (Чистый Go)

- [ ] Инициализация модуля `go.mod` (Go 1.23+).
- [ ] Определение базовых типов: `EngineConfig`, `Status`, `EventBus` (`core/types.go`).
- [ ] Реализация модуля криптографии `core/crypto/`:
  - HKDF-SHA256 деривация ключей (`salt="WDTT-WRAP-v1"`).
  - ChaCha20-Poly1305 AEAD (Seal/Open) с 12-байтным Nonce.
- [ ] Реализация протокола пакетов `core/protocol/`:
  - `rtp.go`: упаковка в контейнер RTP v2 (PT 111 / PT 96) со случайным паддингом.
  - `frame.go`: RA-фрейминг (Magic `0x5241`, `seq uint32`, кольцевой буфер `rawReorder` со stall-таймаутом 40мс).
  - `flow.go`: 5-tuple симметричное хеширование потоков для Flow Affinity.
- [ ] Написание и прогон юнит-тестов (`core/crypto/wrap_test.go`, `core/protocol/frame_test.go`).
- **Критерий готовности**: 100% прохождение тестов на шифрование, распаковку и переупорядочивание потерянных/перепутанных пакетов.

---

## 📌 Этап 2: Двухрежимный локальный сетевой мост (Dual LAN Bridge)

- [ ] Реализация мультиплексирующего листенера `core/bridge/dual_listener.go` на порту `24066`:
  - Сниффинг первого входящего байта (`0x05` ➔ SOCKS5, иначе ➔ HTTP CONNECT).
- [ ] Полнофункциональный RFC 1928 SOCKS5 хендлер (IPv4, Доменные имена, UDP Associate).
- [ ] RFC 7231 HTTP Proxy хендлер (метод `CONNECT` и обычный HTTP).
- [ ] Модуль локального обнаружения `core/bridge/mdns.go` (анонсирование `netturn.local`).
- [ ] Юнит-тесты на автоопределение протоколов и проксирование трафика.
- **Критерий готовности**: подключение браузера через порт `24066` как по SOCKS5, так и по HTTP Proxy.

---

## 📌 Этап 3: Клиент VK Calls API и трехуровневая капча

- [ ] Браузерный HTTP клиент на базе `bogdanfinn/tls-client` (профили Chrome 130+, JA3/JA4 отпечатки).
- [ ] Пайплайн авторизации `core/vk/auth.go`:
  - Получение токена сообщений (`login.vk.ru`).
  - Проверка звонка (`calls.getCallPreview`).
  - Получение токена участника (`calls.getAnonymousToken`).
  - Вход в медиа-сессию OKCDN (`calls.okcdn.ru/fb.do`) и извлечение TURN-креденшелов.
- [ ] Модуль капчи Level 1 (`core/vk/captcha/`):
  - Парсинг bootstrap HTML страницы `redirect_uri`.
  - Многопоточный вычислитель SHA-256 PoW.
  - Пайплайн `captchaNotRobot` (settings, componentDone, check, endSession).
- [ ] Пул звонков `core/vk/pool.go` (ротация хешей, мониторинг доступности).
- **Критерий готовности**: автономное получение актуальных TURN-креденшелов по хешу звонка без открытия браузера.

---

## 📌 Этап 4: Транспорт TURN и диспетчеризация воркеров

- [ ] Интеграция Pion TURN (`core/turn/`):
  - Создание клиентских аллокаций (UDP / TCP-STUN).
  - Каскадный запуск групп воркеров (по 9 воркеров с задержкой 100–300 мс).
- [ ] Диспетчер трафика `core/rawtun/dispatcher.go`:
  - Flow Affinity (привязка 5-tuple сессий к воркерам с TTL 3 мин).
  - Flow Dwell (чанкинг пакетов для предотвращения TCP out-of-order).
- [ ] Реализация хэндшейка `RAWCONF` / `RAWCHAL` (выдача IP `10.70.x.y`).
- **Критерий готовности**: успешный обмен датаграммами между двумя узлами через релеи OKCDN.

---

## 📌 Этап 5: Сетевой адаптер Linux и маршрутизация

- [ ] Linux TUN драйвер `core/rawtun/tun_linux.go` (`/dev/net/tun`, `IFF_TUN | IFF_NO_PI`).
- [ ] Абстракция `core/rawtun/tun_android.go` для приема `fd` от VpnService.
- [ ] Модуль маршрутизации `core/network/route_linux.go`:
  - Определение дефолтного шлюза и физического интерфейса.
  - Добавление `/32` исключений к VPS и TURN-релеям.
  - Применение префиксов `0.0.0.0/1` и `128.0.0.0/1`.
- [ ] Фоновый страж `core/network/watcher.go` (TCP 53 зондирование, автоадаптация шлюзов).
- [ ] Сборка консольного клиента `cmd/netturn-client`.
- **Критерий готовности**: полноценный туннель на Linux через консоль с работающим интернетом.

---

## 📌 Этап 6: Серверная инфраструктура VPS

- [ ] Серверный демон `cmd/netturn-server`:
  - Слушатель WRAP RTP сокета.
  - TUN-интерфейс `netturn0` (подсеть `10.70.0.0/16`).
  - Управление сессиями и многопользовательская база паролей.
- [ ] Скрипт развертывания `server/deploy/deploy.sh` (Ubuntu 22.04/24.04, Debian 12):
  - Настройка `iptables MASQUERADE` и `TCPMSS --clamp-mss-to-pmtu`.
  - Установка и автозапуск через `systemd`.
- **Критерий готовности**: развертывание чистого VPS за одну команду: `bash <(curl -sL .../deploy.sh)`.

---

## 📌 Этап 7: Пользовательские интерфейсы (Desktop & Mobile)

- [ ] **Linux Desktop GUI (`desktop/`)**:
  - Инициализация Wails v2 + React + TypeScript + Tailwind CSS.
  - Интерактивный виджет Connection Pipeline.
  - Мониторинг скорости в реальном времени (Canvas графики), RTT и сессионного трафика.
  - Нативный системный трей с управлением в 1 клик.
  - Вкладка LAN-моста с QR-кодом и mDNS.
- [ ] **Android Приложение (`android/`)**:
  - Gomobile сборка ядра в `.aar`.
  - Android `VpnService` реализация.
  - Jetpack Compose UI в едином дизайн-коде.
  - Quick Settings Tile в шторке Android.
- **Критерий готовности**: готовые релизные пакеты (`.deb`/AppImage для Linux, `.apk` для Android).
