# Сетевая подсистема и маршрутизация (Внутренняя документация)

> **Статус**: Архитектурная спецификация  
> **Целевые платформы**: Linux Desktop (`/dev/net/tun`), Android (`VpnService`)  

Документ описывает принципы работы с виртуальными адаптерами, методы предотвращения петель маршрутизации, алгоритмы split-tunneling (обход блокировок) и систему мониторинга сетевых интерфейсов.

## 1. Защита от петель маршрутизации (Routing Loop Prevention)

При перенаправлении всего сетевого трафика через виртуальный адаптер критически важно исключить из туннеля служебный трафик самого клиента:
1. Соединения к медиа-релеям VK (`calls.okcdn.ru`, пулы `91.231.x.x`, `90.156.x.x`).
2. Соединения к VPS серверу NetTurn (`peerAddr`).

Если этот трафик попадет в созданный виртуальный адаптер, возникает петля: пакеты туннеля будут инкапсулироваться сами в себя, и связь моментально разорвется.

### 1.1. Алгоритм изоляции на Linux Desktop
```
[Старт NetTurn]
      │
      ▼
1. Запрос физического шлюза по умолчанию
   (через Netlink или чтение /proc/net/route)
   Получаем: GwIP (например, 192.168.1.1) и Iface (например, wlan0)
      │
      ▼
2. Добавление строгих /32 маршрутов через физический шлюз:
   ip route add <VPS_IP>/32 via <GwIP> dev <Iface>
   ip route add <TURN_RELAY_IP>/32 via <GwIP> dev <Iface>
      │
      ▼
3. Перехват глобального трафика через два покрывающих префикса:
   ip route add 0.0.0.0/1 dev netturn0
   ip route add 128.0.0.0/1 dev netturn0
```

#### Почему префиксы `/1`, а не удаление `default via`:
Префиксы `0.0.0.0/1` и `128.0.0.0/1` имеют более длинную маску (длина префикса 1 бит), чем стандартный маршрут по умолчанию `0.0.0.0/0` (0 бит). Согласно правилу Longest Prefix Match, ядро Linux отправляет весь трафик в `netturn0`, но не трогает системную таблицу. В случае аварийного завершения процесса или падения туннеля ОС мгновенно возвращается к обычному интернету без "зависания" сети.

## 2. Адаптивный сетевой наблюдатель (Adaptive Sleep Watcher)

В процессе работы клиент может менять сетевое окружение:
- Переключение с домашнего Wi-Fi на мобильный интернет или другую сеть.
- Переход ПК в спящий режим и последующее пробуждение.
- Смена IP-адреса локального шлюза при роуминге DHCP.

### Алгоритм работы:
1. Фоновый поток с интервалом в 2 секунды отправляет контрольный TCP SYN зонд на известный DNS-сервер (`77.88.8.8:53`) через физический интерфейс с таймаутом 800 мс.
2. При сбое зонда или обнаружении события `RTM_NEWROUTE` / смены интерфейса:
   - Включается режим паузы передачи данных (freeze воркеров).
   - Запрашивается новый физический IP шлюза.
   - Обновляются `/32` маршруты к VPS и TURN-серверам.
   - Сессия возобновляется без полного разрыва соединения и без пересоздания TUN-адаптера.

## 3. Особенности реализации на Android (VpnService)

На платформе Android архитектура разделяется на две части:

1. **Kotlin (Android Runtime)**:
   ```kotlin
   val builder = Builder()
       .setSession("NetTurn")
       .setMtu(1280)
       .addAddress("10.70.x.y", 16)
       .addRoute("0.0.0.0", 0)
       .addDnsServer("1.1.1.1")
       .addDisallowedApplication(packageName) // Исключаем сам NetTurn из VPN!
   
   val pfd = builder.establish()
   val fd = pfd.detachFd()
   // Передаем fd в Go ядро
   NetTurnCore.startWithFd(fd, configJson)
   ```
2. **Go Core**:
   ```go
   // tun_android.go
   file := os.NewFile(uintptr(fd), "tun")
   return &AndroidTun{file: file, mtu: 1280}, nil
   ```
- Метод `addDisallowedApplication` на уровне Android OS предотвращает петли маршрутизации, так как сокеты Go-рантайма автоматически не маршрутизируются в созданный `VpnService`.

## 4. MTU и TCP MSS Clamping

Поскольку сырой IP-пакет инкапсулируется в `RA-Frame (6B)` + `ChaCha20-Poly1305 Tag (16B)` + `RTP Header (12B)` + `Padding (до 60B)` + `UDP/TURN/IP (до 48B)`, эффективный размер MTU уменьшается.

- **Базовый MTU на адаптере**: `1280 байт` (гарантирует отсутствие IP-фрагментации на любых сетях, включая сотовые сети LTE/5G).
- **Серверный TCP MSS Clamping**:
  На сервере VPS обязательно применяется правило iptables:
  ```bash
  iptables -t mangle -A FORWARD -p tcp --tcp-flags SYN,RST SYN -j TCPMSS --clamp-mss-to-pmtu
  ```
  Это правило предотвращает дропы TCP-пакетов при установке TLS-соединений (Handshake Blackhole).
